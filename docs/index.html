全局待办Global todos

一份跨会话的待办清单：一个属于你的文件，你和 Agent 读写同一份，一键交给某个对话继续干。 A cross-session todo list for DeepSeek Harness: one file you own, written by you and your agent, handed to a conversation in one click.

shell · npm 点一下选中整条click to select the line 
dsh plugin add dsh-global-todo

装完要重启宿主（dsh web）再刷新页面。面板只在 Web 客户端；headless、ACP、SDK 拿到的是工具，没有面板。需要 DSH 0.2.x 与 Node ≥ 22.19。 Restart the host (dsh web) and reload the page. The panel exists only in the Web client; headless, ACP and SDK get the tools without it. Requires DSH 0.2.x and Node ≥ 22.19.

三件事 Three claims

会话级计划做不到的三件事 Three things a session-local plan cannot do

DSH 自带的 todo_write 属于某一个 agent 会话：整表替换、三个状态、会话一关计划就翻篇。这份清单补的不是功能数量，是归属。 The built-in todo_write belongs to one agent session: whole-list replacement, three states, and a plan that ends when the session does. This list is about ownership, not feature count.

01

一个 JSON 文件就是全部 One JSON file is the whole list

清单在 $DSH_HOME/global-todo/todos.json：没有数据库，没有服务端。能 cat、能 diff、能提交进仓库、能丢进同步盘，拷到另一台机器就接着用。 The list lives at $DSH_HOME/global-todo/todos.json: no database, no server. cat it, diff it, commit it, drop it in a sync folder, copy it to another machine. 

{
  "version": 1,
  "todos": [{
    "id": "t-4f1a9c02",
    "title": "等交换机到货后重测内网吞吐",
    "createdAt": 1768867200000,
    "steps": [{ "text": "换上万兆模块", "done": false }]
  }]
}

写入走「临时文件 + rename」，人和 Agent 的改动串在同一把写锁后面；文件坏了报 store-corrupt，不会静默清空。 Writes go to a temp file and are renamed into place, behind one lock shared by panel and tools. A corrupt file raises store-corrupt instead of being silently emptied.

02

交接是一个按钮 Hand-off is a button

四种模式：current 当前对话、auto 先复用已绑定的会话、new 总是新开、bound 只发已绑定的那个。新会话要工作目录，所以派发前会检查；三者都定位不到就明确拒绝并说明原因。 Four modes: current, auto (reuse the bound conversation first), new, and bound. A new session needs a working directory, so the hand-off checks it and refuses with a reason when none can be found.

待办自己的 steps[] 原样变成派发提示词里的编号计划；成功和失败都记在记录上。 The todo's own steps[] arrive as the agent's numbered plan. Success and failure are both recorded on the record.

03

Agent 说「做完了」是声明，不是事实 An agent's “done” is a claim until a person confirms

以 agent 身份完成会落到 review = pending，行上显示「待确认」。人点确认，它才算完成；人点退回，它回到清单，那条完成记录一并清掉。 Finishing as an agent sets review = pending and the row shows 待确认. Confirm it and it stays finished; send it back and it returns to the list with its completion record cleared.

待确认Needs review 确认完成Confirm 退回清单Send back

只有干净收尾的回合才自动完成：error、aborted、interrupted、max-tokens 一律留着未完成——标错一次，整份清单就不值得信了。 Only clean turns auto-complete: error, aborted, interrupted and max-tokens leave the todo open. One wrong “done” would make the whole list untrustworthy.

一条待办的路径 The path of one todo

从一句话，到一个被确认的结果 From one sentence to a confirmed result

五步。每一步下面都是面板真实渲染出来的截图，由 npm run screenshots 生成；点开看原尺寸。 Five steps. Every image below is a real panel state rendered by npm run screenshots; click one for full size.

  1. 01

    抓取Capture

    你在对话里说一句「记一下：等交换机到货后重测内网吞吐」，或让 Agent 用 global_todo_capture 一次抓几条。原话作为 evidence 逐字保留，不转述；外部写入的先停收件箱。 Say it once, or let the agent record it with global_todo_capture. The sentence it came from is kept verbatim as evidence; externally written items wait in the inbox.

  2. 02

    拆成步骤Break into steps

    一条待办可以带 steps[]：行上显示「步骤 2/4」，派发时按顺序编号。五步的活不需要第二个对象。 A todo can carry steps[]: the row shows 步骤 2/4, and the hand-off prompt numbers them. Five-step work does not need a second object.

  3. 03

    交接Hand off

    选 交给：[对话名]，或多选后按「一键分配」。能复用已绑定的会话就复用；配不上的报回来并给选择器，不擅自送到别处。 Pick 交给：[conversation], or select rows and use 一键分配. A bound conversation is reused when possible; anything unmatched comes back with a picker instead of being sent somewhere else.

  4. 04

    读回那个对话Read it back

    面板显示它「在跑」还是「已休眠」、最后说的几句（缓存 400 字），旁边有按钮跳过去。交接不再发出去就没下文。 The panel says whether it is running or dormant, shows its last words (400 cached characters), and links to it. No more fire-and-forget.

  5. 05

    确认Confirm

    Agent 的完成先进「待确认」：人点「确认完成」，或「退回清单」。同一行还能看到完成说明和这轮改过的文件。 An agent completion waits in 待确认. Confirm it, or send it back; the row carries the closing summary and the files that turn changed.

  • 没有看板视图。清单是列表加分组的，没有列、没有拖拽、没有泳道。 No kanban view. The list is a list with groups: no columns, no drag, no swimlanes.
  • 没有日历。只有到期时间和到点提醒，没有月视图、周视图。 No calendar. Due times and due reminders, no month or week view.
  • 没有子任务工单。steps[] 是待办内部的勾选项，不能单独派发，也不能各自挂附件。 No sub-task tickets. steps[] are ticks inside one todo; they cannot be dispatched on their own or carry their own attachments.
  • 不会定时开工。ROADMAP 把「自动跑待办」写进「不计划」：那需要一个任务队列，而这是一份个人清单。 No scheduled execution. ROADMAP lists “auto-running todos” under not planned: that is a job queue, and this is a personal list.

另外两条刻意的取舍：附件是引用不是上传（不复制字节，带用户名密码的网址一律拒绝）；可选服务缺失就降级——没有 agents 时按钮报 agents-unavailable，面板其余部分照常工作。 Two deliberate trade-offs behind this: attachments are references, not uploads (no bytes copied, and URLs with a user and password are refused), and a missing optional service degrades instead of breaking — without agents the button reports agents-unavailable while the rest of the panel keeps working.

条件状态 Conditional states

每一种状态都有基线图 Every state has a baseline image

只在特定情况下出现的界面（空清单、无结果、收件箱、待确认、提醒、批量选择、设置、深色）各有一张固定基线图。改样式时直接对比，不用凭记忆。 Each state that only appears under a condition — empty, no results, inbox, review, reminders, selection, settings, dark — has a fixed baseline. Compare against it instead of remembering.
