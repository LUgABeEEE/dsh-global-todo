全局待办Global todos

一份跨会话的待办清单：一个属于你的文件，你和 Agent 读写同一份。它最要紧的一条规则是 Agent 说的「做完了」不算完成——不管是工具里报的，还是交给的会话干净收尾后自动收尾的，都只进「待确认」，你点头才算。待办还能带步骤，交出去时按编号一起交。 A cross-session todo list for DeepSeek Harness: one file you own, written by you and your agent. Its one hard rule is that an agent’s “done” is not completion — whether it reports that from a tool or the host infers it when a dispatched conversation ends cleanly, the record waits in Needs review until you confirm it. Items also carry steps, which ship as a numbered plan.

三件事 Three claims

会话级计划做不到的三件事 Three things a session-local plan cannot do

DSH 自带的 todo_write 属于某一个 agent 会话：整表替换、三个状态、会话一关计划就翻篇。这份清单补的不是功能数量，是归属。 The built-in todo_write belongs to one agent session: whole-list replacement, three states, and a plan that ends when the session does. This list is about ownership, not feature count.

01

Agent 说「做完了」只是声明，两个入口一样 An agent's “done” is a claim — from either door

它自己在工具里报完成，是一种声明；交给的会话干净收尾、宿主替它收尾，是另一种。两条路都只把记录送进 review = pending：人点「确认完成」才算完成，点「退回清单」就回到清单里，完成记录一并清掉。 Reporting done from a tool is a claim; so is the host closing the todo when a dispatched conversation ends cleanly. Both land in review = pending: a person confirms, or sends it back — completion record and all.

待确认Needs review 确认完成Confirm 退回清单Send back

只有干净收尾的回合才是候选：error、aborted、interrupted、max-tokens 一律留着未完成——标错一次，整份清单就不值得信了。 Only clean turns are candidates: error, aborted, interrupted and max-tokens leave the todo open. One wrong “done” would make the whole list untrustworthy.

02

一个 JSON 文件就是全部 One JSON file is the whole list

清单在 $DSH_HOME/global-todo/todos.json：没有数据库，没有服务端。能 cat、能 diff、能提交进仓库、能丢进同步盘。两台机器要共用一份时，各自留一份本地文件、在一个碰头目录里折成一份——按记录合并，删除靠墓碑传播，离线也不会互相覆盖。 The list lives at $DSH_HOME/global-todo/todos.json: no database, no server. cat it, diff it, commit it, drop it in a sync folder. Two machines share one list by keeping their own file and folding through a hub directory — per record, with deletions carried as tombstones, so being offline cannot overwrite anyone. 

{
  "version": 2,
  "todos": [{
    "id": "t-4f1a9c02",
    "title": "等交换机到货后重测内网吞吐",
    "createdAt": 1768867200000,
    "steps": [{ "text": "换上万兆模块", "done": false }]
  }],
  "trash": [{ "id": "t-1c0d7e44", "at": 1768953600000, "by": "human" }]
}

写入走「临时文件 + rename」；同一进程里人和 Agent 共用一条串行链，跨进程还有一把 .lock 独占锁——第二个宿主进程只能排队，等不到就报 store-busy，不会默默覆盖。文件坏了报 store-corrupt，不会静默清空。trash 是删除留下的墓碑：没有它，另一台机器手里的旧副本会把记录原样带回来。 Writes go to a temp file and are renamed into place; panel and tools share one serial chain, and a .lock file excludes other processes — a second host queues, then hears store-busy instead of silently overwriting. A corrupt file raises store-corrupt. trash holds the tombstones; without them another machine's older copy would bring a deleted record straight back.

03

交接是一个按钮 Hand-off is a button

四种模式：current 当前对话、auto 先复用已绑定的会话、new 总是新开、bound 只发已绑定的那个。新会话要工作目录，所以派发前会检查；三者都定位不到就明确拒绝并说明原因。 Four modes: current, auto (reuse the bound conversation first), new, and bound. A new session needs a working directory, so the hand-off checks it and refuses with a reason when none can be found.

一条待办的路径 The path of one todo

从一句话，到一个被确认的结果 From one sentence to a confirmed result

五步。每一步下面都是面板真实渲染出来的截图，由 npm run screenshots 生成；点开看原尺寸。 Five steps. Every image below is a real panel state rendered by npm run screenshots; click one for full size.

  1. 01

    抓取Capture

    你在对话里说一句「记一下：等交换机到货后重测内网吞吐」，或让 Agent 用 global_todo_capture 一次抓几条。原话作为 evidence 逐字保留，不转述；外部写入的先停收件箱。 Say it once, or let the agent record it with global_todo_capture. The sentence it came from is kept verbatim as evidence; externally written items wait in the inbox.

  2. 02

    拆成步骤Break into steps

    一条待办可以带 steps[]：行上显示「步骤 2/4」，派发时按顺序编号。五步的活不需要第二个对象。 A todo can carry steps[]: the row shows 步骤 2/4, and the hand-off prompt numbers them. Five-step work does not need a second object.

  3. 03

    交接Hand off

    选 交给：[对话名]，或多选后按「一键分配」。能复用已绑定的会话就复用；配不上的报回来并给选择器，不擅自送到别处。 Pick 交给：[conversation], or select rows and use 一键分配. A bound conversation is reused when possible; anything unmatched comes back with a picker instead of being sent somewhere else.

  4. 04

    读回那个对话Read it back

    面板显示它「在跑」还是「已休眠」、最后说的几句（缓存 400 字），旁边有按钮跳过去。交接不再发出去就没下文。 The panel says whether it is running or dormant, shows its last words (400 cached characters), and links to it. No more fire-and-forget.

  5. 05

    确认Confirm

    Agent 的完成先进「待确认」：人点「确认完成」，或「退回清单」。同一行还能看到完成说明和这轮改过的文件。 An agent completion waits in 待确认. Confirm it, or send it back; the row carries the closing summary and the files that turn changed.

手机端 On a phone

手机上，一屏读完的清单 A list a phone can read in one screen

面板按自己的实测宽度切换，≤600px 就是触控布局——DSH Mobile 的手机页不用任何配置，桌面窗口拖窄也是同一套。向下滑收起搜索那一行，每条待办收成「标题 + 一行信号」：390×844 下 66px 一行，第一屏就能看八条左右。 The panel switches on its own measured width: 600px or less is the touch layout. DSH Mobile's phone page needs no configuration, and a narrow desktop window gets the same treatment. Scrolling down folds the search line away and every row becomes one title line plus its signals — 66px per row at 390×844, about eight on the first screen.

  • 折叠是手势，不是开关。向下滑 80px 收起搜索行，还要越过它让出的 110px；向上滑 48px 或回到顶部展开。翻面后 300ms 内不响应，拇指停在边界上也不会抖。 The fold is a gesture, not a switch. 80px down folds the search line away and it must clear the 110px that frees; a 48px flick up, or the top, unfolds it. Either direction is deaf for 300ms after a flip, so a resting thumb cannot oscillate.
  • 收起后只剩标题 + 一行信号：截止、优先级、待确认、完成时间；打开着的那条保持完整，附件芯片淡出而不是硬消失。 Folded, a row is its title plus one line of signals — deadline, priority, review, completion time. The open row stays whole; attachment chips fade instead of vanishing.
  • 三种分组一直可见：工作区 / 时间 / 待办等级，横排标签，不随折叠收起。「工作区」按写下这条待办的目录分组，组头就是目录名。 All three group modes stay visible — workspace / time / priority — and the fold never takes them away. “Workspace” groups by the directory the work was written in.
  • 手机上不摆没用的开关：「交给 / 上下文」与「自动获取」搬进设置面板（桌面照旧），「选择」挪到搜索框后面，工具栏只剩筛选、搜索、分组三行。 No dead switches on a phone: the dispatch summary and the auto-collect switch moved into settings (the desktop keeps them), selection moved next to search, and the toolbar is filters, search, grouping.
  • 触摸与安全区：按钮、输入框、筛选胶囊 44px；筛选横滑而不是被裁掉；行内「交给 Agent」收成图标；底部让出安全区；正文跟随手机页字号，输入框不小于 16px（否则 iOS 会替你放大页面）。 Touch and safe areas: 44px buttons, inputs and chips; chips scroll sideways instead of being clipped; the inline hand-off becomes its icon; the bottom yields to the safe area; text follows the page's size setting and inputs stay 16px or more.

  • 没有看板视图。清单是列表加分组的，没有列、没有拖拽、没有泳道。 No kanban view. The list is a list with groups: no columns, no drag, no swimlanes.
  • 没有日历。只有到期时间和到点提醒，没有月视图、周视图。 No calendar. Due times and due reminders, no month or week view.
  • 没有子任务工单。steps[] 是待办内部的勾选项，不能单独派发，也不能各自挂附件。 No sub-task tickets. steps[] are ticks inside one todo; they cannot be dispatched on their own or carry their own attachments.
  • 不会定时开工。ROADMAP 把「自动跑待办」写进「不计划」：那需要一个任务队列，而这是一份个人清单。 No scheduled execution. ROADMAP lists “auto-running todos” under not planned: that is a job queue, and this is a personal list.

另外两条刻意的取舍：附件是引用不是上传（不复制字节，带用户名密码的网址一律拒绝）；可选服务缺失就降级——没有 agents 时按钮报 agents-unavailable，面板其余部分照常工作。 Two deliberate trade-offs behind this: attachments are references, not uploads (no bytes copied, and URLs with a user and password are refused), and a missing optional service degrades instead of breaking — without agents the button reports agents-unavailable while the rest of the panel keeps working.
